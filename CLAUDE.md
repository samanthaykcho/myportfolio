# Samantha Cho — industrial design portfolio

Static site (plain HTML/CSS/JS, no build step). Repo: https://github.com/samanthaykcho/myportfolio (branch `main`; renamed from `portfolio2`). Hosted on GitHub Pages: https://samanthaykcho.github.io/myportfolio/ (deploys from `main`, root).
Open `index.html` directly in a browser to view it.

## Working with Sam
- **Do all the coding yourself.** Sam wants to do as little coding work as possible — never hand her code to paste.
- **Ignore prefers-reduced-motion entirely.** Don't add reduced-motion rules.
- **Intuitive design comes first**, over flashy effects.
- She likes to be **asked for an opinion before bigger changes** — give a recommendation, then build when she says go.
- **Commit / push only when she asks.**
- Keep copy lowercase-and-friendly in UI labels (nav, captions); résumé content keeps normal capitalization.
- You can't see the site in a browser here (Playwright MCP times out; starting a local server is blocked). Say so when a change needs her eyes, and ask for screenshots.

## Structure
- `index.html` holds **both views**: `#home-view` (title page + white "work" contents sheet + footer) and `#about-view` (bio, "currently…", résumé, contact form). `about.html` is just a redirect to `index.html#about`.
- `script.js` sections, in order: Lenis smooth scroll → tagline intro animation → Variable Proximity (cursor-weight effect on `.vp` elements, spring "sticky" pull) → name rounding filter → background video (0.5× speed, blur ramps at loop ends) → water ripples → custom cursor → scroll reveal (`.project`, `[data-reveal]` get `.in`) → parallax → nav + hash router → contact form → lightbox (`[data-zoom]` buttons open `#lightbox`; closes on outside click, ×, Esc, back; plain overlay not `<dialog>` so the custom cursor stays on top).
- Router: hashes `#work`, `#about`, `#contact`, `#`, plus one per project page (`#isogu`). Any page slides in from the right (WAAPI, `showPage`; `current` tracks the showing page, null = home), home slides back (`showHome`; back button returns to the saved scroll spot), contact = show about then Lenis-scroll to `#contact` (call `lenis.resize()` first — the about view is position:fixed during the slide).
- Project pages: `<div class="view view--project" id="<name>-view" data-title="<name>" hidden>` > `main.case`. The router picks them up automatically from the id; the card links to `#<name>`. Hero = full-screen `.case-hero` (`.case-hero-img` photo, cover, + `.case-logo` floating above the product — Sam's chosen look); below it a white `.case-sheet` (like the work sheet) with `.case-intro` (num + skills) then story sections: `.case-section` > `.case-heading` (no label above it — Sam dropped "the problem") (big lowercase, rounded by SVG filter `#round-head` to mimic Sam's 5% Illustrator path smoothing) + `.case-pair` (two 3:2 `.case-fig` photos, 2nd dropped 12vh) + `.case-takeaway` (big "so what" line under the right column). Then `.case-hcw`: the "how can we" design question, big + centred, key phrases in `<em>` (blue). Then "research": `.case-block`s with `.case-sub` subheads — `.case-compare` (3 `.case-option` columns, `.proscons` list with blue + / grey − marks and `.sr` screen-reader text) and `.case-criteria` (numbered rows: `.crit-name` + `.crit-desc`). Then "ideation" (no intro paragraph — Sam said the one I wrote didn't sound like her; don't write copy in her voice without asking): `.case-sketches` (sketchbook pages `isogu-sketches-1/2.webp`, rendered from `MATCHA SKETCHES.pdf` with mupdf in the scratchpad, rotated -90°, spine cropped; side by side, straight, no frame — each a `button.sketch-paper[data-zoom]` that opens the `#lightbox` overlay), then `.case-concepts` (3 trimmed digital sketches `isogu-concept-1/2/3.webp` from `concept<n>sketch.PNG`: 1 = drawer jar, 2 = spout tin + measuring lid, 3 = whisk-shaped bamboo tin; labels "concept n") and `.case-eval` (concept evaluation + extra notes — Sam's exact wording, don't edit; a `.link-btn[data-zoom-panel="matrix-tpl"]` opens the evaluation matrix, an HTML table in `<template id="matrix-tpl">`, in the lightbox. Matrix: 0 = existing products baseline, concepts scored +/− relative to it; (n) = category max). Concepts are introduced by Sam's line "I took 3 of the best concepts digital…" and labelled with their matrix names. Concept labels are capitalized ("Concept 1", "Concept A") everywhere, matrices included — Sam's call. Then "prototyping": Sam's intro line, `.case-protos` (cardboard prototypes cut out with @imgly/background-removal-node: `isogu-proto-tin.webp` = concept A Tin with Spout, `isogu-proto-whisk.webp` = concept B Whisk with Sieve, cast shadow masked out by a traced polygon and rotated upright (tube on top); note imgly pins an old sharp — run it in its own script, never in the same process as sharp 0.35), `.case-testing` (`.test-grid`, 4 across × 2 rows, kept small: `isogu-testing-1,2,3,5,6.webp` = tin tests from IMG_4657/4681/4762/4774/4775, `7..9` = whisk tests from IMG_4663/4689/4778; #4 (IMG_4765) was cut by Sam; originals ignored), `.case-eval` with prototype feedback + next steps (her wording) and a link to `#matrix-post-tpl` (post-prototype matrix + her summary). Then "development" (Sam's wording, only capitalization fixed): initial cad (`.cad-row`, 3 zoomable `isogu-cad-initial-1..3.webp`), first print (`.case-split`: cut-out `isogu-print-1.webp` from tin3dprint1.JPG + text), redesigns (`.case-split--flip`: text with `mark.hl` pop-ups on "multi-leveled tea fields" / "bamboo silhouette" — `pop-tea-fields.webp` / `pop-bamboo.webp` from her stock photos — + zoomable `isogu-redesigns.webp`), refined cad (`isogu-cad-parts.webp` from new cad.png, then `isogu-cad-refined.webp` from cad 1.png cropped to drop the Fusion view cube). `.case-sheet .hl` = light-blue band variant. Then "final manufacturing" (Sam's notes; only fixed typos Rustoleom→Rust-Oleum, Automitive→Automotive): `.make-phase` blocks (text + `.make-steps` numbered, zoomable photos `isogu-make-1..7.webp`; phase 2 `--flip`, last photo full width). Then "branding" in four rows: logo evolution (`isogu-logo-sketch.webp` → `isogu-brand-logo.webp`), `.brand-story` Q&A (her words from the brand board), type + colour (`isogu-brand-type.webp` specimen + `.swatches` blue #447FC1 / cream #ECE5D7 — her brand colours), label (`isogu-brand-label.webp` beside make-7) + "view full brand board" link (`data-zoom-src` opens an image in the lightbox). Brand exports came from her Downloads (isogu branding [Recovered].png, isogu label.png, isogu typeface.png). Then "final": `.case-final` with a full-bleed, full-screen `isogu-final.webp` (from isogu context.png), then `.case-end` bar (← back to work / next project: kove →, `a.case-link`, routed). kove/nimi pages have `a.back.back--fwd` "next project" links: kove → nimi → isogu. Possible later: reflection. Planned order after: prototyping → cad + details → brand + cmf → final (isogu.jpg) → reflection. The hero pushes in with the slide, logo trails. Nav is dark across project pages; cursor is white over the hero photo (Sam's call), blue over the sheet. On a project page, nav "work" sits heavier (aria-current).
- Section index on project pages: built in script.js (before Variable Proximity, so its names are `.vp`) from each `.case-section`'s `.case-heading` — new sections appear automatically; each section gets an id like `isogu-context`. Fixed in the left margin at ≥1380px, a blue "sections" pill at the bottom below that. Shows once the white sheet passes mid-screen; current section is blue + heavier; clicking glides there with Lenis.
- Top nav (work / about / contact) tucks away (`.nav.tucked`) once the white work sheet covers the screen; the same links live in the work page's `.foot` footer.
- Font: Adobe Fonts kit `tfd3zvu`, family `acumin-variable` (weight animated via `font-variation-settings`).
- Easing tokens in `:root`: `--ease-out: cubic-bezier(0.23,1,0.32,1)`; view slide uses `cubic-bezier(0.77,0,0.175,1)`.
- Contact form posts to Web3Forms (access key in `data-key` on `#contact-form`), so her email is never on the page. Has a `botcheck` honeypot.

## Background colourways
- Two background videos, picked with round swatches at the end of the top nav (`.cw-picker` > `button.cw[data-cw]`): **aquarium** (`aquarium.mp4`, default) and **dark** (`dark.mp4`, from dark mode.MOV). A coral colourway was tried and removed by Sam. Videos made with ffmpeg-static in the scratchpad: 960px wide, H.264 CRF 27, no audio, faststart (~2–3MB).
- Choice lives on `<html data-colourway>`, saved in localStorage; an inline script in `<head>` applies it before paint. Each colourway sets `--tint` / `--tint-opacity` / `--bg-base` and `--hl-band` (bio highlight band: navy / site blue) in style.css. Switching cross-fades (`.bg.swapping`).
- Sam chose option A for dark mode: only the video + tint change; the white sheets stay white. The coral videos (coral calm/lively.MOV, ignored) aren't used.

## Water ripples + cursor
- The video is redrawn on WebGL canvas `#bg-water` and **bent only** (refraction) by a CPU wave sim around the cursor; tuning constants sit at the top of the "Water ripples" section. Sam approved this look.
- Rejected: lit/shaded glints on the waves (looked like "bumps on skin"), and long trails that spread across the screen. Keep it bend-only, short wake near the cursor.
- Only works when served over http(s) — from `file://` the browser won't share video pixels, so it silently falls back to the plain video. Check on the live site.
- Custom cursor: a bubble (`.cursor` > `.cursor-bubble`, mouse only, via `html.has-cursor`); swells over clickables, pops into a `.cursor-pop` ring on click, blue over the white `.contents` sheet, hidden in text fields. Rare `.cursor-drift` mini-bubbles float up over the video only (tuning constants at the top of the "Custom cursor" section). Sam wants it aquatic but low-key.

## Work grid (contents sheet)
- Two-column grid in `.projects`; cards are `a.project` (num + title `.vp`, `.frame` > `.media` img, optional `.cutout`, `.desc`). Order: 01 isogu, 02 kove, 03 nimi.
- Zig-zag: card 2 drops 16vh; later left-hand (odd) cards pull up -16vh so rows don't inherit the drop. `row-gap: 6vh` (Sam asked for it tight). Left cards use `data-speed="0"`, right cards `0.09` (parallax).
- Adding a card: frame image 1200×1200 jpg; cut-out positioned in % of the frame (`.cutout--name`). If a cut-out dips below the frame, narrow that card's `.desc` (nimi uses `.desc--clear-spill`, 58%).
- Sam's naming taste: short, soft, lowercase product names (isogu, kove, nimi).

## Bio pop-ups
Highlighted phrases (`mark.hl`) show a polaroid (`.pop` with `img` + `.cap`) on hover/focus. Thumbnails are `assets/pop-*.webp`, 600px wide, uncropped, made with sharp (`.rotate().resize({width:600}).webp({quality:84})`). HEIC files need converting first (sharp can't read them; WPF BitmapDecoder works).
